# Interface decisions

One top bar holds the collection and review selectors, so navigation stays out of the diff’s way. In the review selector, a review linked to a pull request shows the PR’s state under its progress, plus its checks and any approval or requested changes while it’s open; opening the selector re-reads them. The PR’s link stays in the review header, because a link inside a list option can’t be reached by keyboard. Collections express a curated reading order; the separate Git ancestry tab reports actual dependencies. Each review and change group leads with a human name and explanation; a review description past three lines folds behind Show more. The branch and a plain-language summary of the comparison share the tab row, and the folder, mode, and base open from that summary. Beside them, the line count covers runtime code only, so tests, evals, and lockfiles don’t inflate it; hovering or clicking it shows each kind and the total. A commit SHA base stays out of the summary because it tells the reader nothing. Diff layout, whitespace, wrapping, and theme sit behind one settings button.

The file outline is an index into a continuous review, not a single-file filter. Within each group, files sit under a row for their folder; a long folder drops its leading folders rather than cutting through a name. Each file takes one line: an icon for its kind (code, test, styles, docs, config, data, SQL, script, lockfile, image, and a few more), its name, and a meter of its changed lines, green for added and red for removed, on a log scale so a one-line fix and a 500-line rewrite both read at a glance. Modified files carry no letter; new, deleted, renamed, and untracked files keep theirs, because the meter can't tell a new file from one that only gained lines. Hovering a file shows its full path, status, kind, and exact line counts, and hovering a shortened folder shows all of it. Dragging the outline's edge, or pressing arrow keys on it, widens it for long folders, up to half the window; the browser keeps that width, and a double-click or Enter restores the default. Kinds differ by shape, not color, because color already means added, deleted, or renamed. A renamed file's card title reads old path → new path, with the changed folders and name parts marked like changed words in a diff, and outline search matches old paths too. A file whose diff has no lines to show, such as a pure rename, says what changed instead of drawing an empty diff. Every changed block appears in its assigned group or Other changes. Whole-file and partial-file groups share the same review controls; partial selections include complete hunks with context and are labeled Selected blocks. A changed image shows each version that exists, stacked in unified view and side by side in split view, over a checkerboard that shows only through transparency.

A group receipt records the diff content and description the user reviewed. Missing selections and overlapping groups are explicit states. While groups are left, the review title carries Mark review viewed and the collection page carries Mark collection viewed; each marks the remaining groups as their own buttons would, skips groups that need attention, and leaves a review untouched, saying why, if its content changed after the page loaded. Reviewed does not imply approval to push or publish. Group status and Viewed marks live on disk; private notes remain browser-local.

Light and dark palettes use semantic tokens for canvas, surfaces, text, borders, syntax, additions, deletions, warnings, and focus. System is the initial preference. Syntax-highlight spans have transparent backgrounds so they cannot erase a diff’s meaning. The change meter’s green and red also differ in lightness, so color-blind readers can still tell them apart. Status text and icons supplement color.

The mark is a pair of reading glasses whose lenses are a diff’s minus and plus, drawn in the canvas color on an accent tile. The wordmark mutes “pre” so “read” leads.

Native buttons, dialogs, and form controls provide keyboard behavior; the custom pickers implement listbox keyboard navigation. Focus remains visible. Reduced-motion disables animation. Narrow screens keep collection navigation and continuous diffs while hiding the optional file outline. Errors, loading, empty comparisons, missing files, and unavailable previews are explicit. A refresh, from the toolbar or from an agent, re-reads behind the current view and keeps the reader’s place; only a server restart or an explicit page reload replaces the page.
